# Unified Chatbot Workflow Engine — COMPLETED

## Architecture Implemented

### New Engine (`backend/app/services/engine.py`)
Single `ConversationEngine` class replaces 3 duplicated handlers. Data-driven pipeline:

```
handle_message → ConversationEngine.process(db, session, message)
  1. smalltalk/side-question intercept
  2. correction handling (check in-progress first, then detect new)
  3. deterministic field extraction (fast, no LLM)
  4. state-gated merge (BOOKING_MERGE / RESCHEDULE_MERGE / CANCEL_MERGE dicts)
  5. state transition (data-driven per-intent state machines)
  6. side effects (DB: appointment lookup, create, reschedule, cancel)
  7. response generation (static fallback preferred; AI only when needed)
  8. persist + return
```

### Routing
- `conversation_service.handle_message` detects intent for `unified` sessions, returns greeting without processing the intent message (prevents extraction pollution)
- All subsequent messages go through `ConversationEngine.process`
- Intent detection: keyword-based (`detect_intent` in engine.py)
- Non-unified sessions (booking/reschedule/cancel) also route through the engine

## Database Rules

### Duplicate Booking Prevention
`_check_duplicate_booking` in engine.py → calls `apt_svc.find_existing_appointment_by_name_phone(db, full_name, phone)`:
- Same name + same phone + upcoming appointment → BLOCK, offer reschedule/cancel
- Same name + different phone → ALLOW (different patient identity)
- Different name + same phone → ALLOW (different person, same number)

### Reschedule/Cancel Guardrails
- Must locate existing appointment by phone before proceeding
- If no appointment found → graceful "couldn't find" message, stay in identifier state
- Uses `apt_svc.find_upcoming_by_phone` for deterministic lookup

## Remaining Limitations / Follow-up

- **`extract_reason`** doesn't match bare words like "checkup" without a verb prefix ("I need a checkup" works, "checkup" alone doesn't)
- **Unified intent detection** is keyword-based — ambiguous messages like "I need help" default to booking
- **Multiple appointments** for same phone: system picks the earliest; no user selection UI yet
- **AI response generation** still runs even when static fallback is sufficient in some states; could be further optimized to skip more AI calls
- **Cancel handler** old code still exists in `conversation_service.py`; could be removed once engine is confirmed stable in production
